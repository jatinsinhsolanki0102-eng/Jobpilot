 3. BELMO DEPLOYMENT ISSUES ENCOUNTERED
 -----------------------------------------------------------------

 ISSUE 1: Nixpacks can't detect Python
   Error: "Nixpacks failed to detect the application type"
   Cause: Root directory has both frontend (Node) and backend (Python).
          Nixpacks detects Node from package.json at repo root.
   Fix Attempt 1: Set Root Directory to ./backend -> Did not work
   Fix Attempt 2: Set Root Directory to backend -> Did not work
   Fix Attempt 3: Created nixpacks.toml in backend/ -> Did not work
   Fix Attempt 4: Created root-level Dockerfile -> Did not work (Belmo
                  still used Nixpacks instead of Dockerfile)
   WORKING FIX:  Created root-level Procfile + requirements.txt ->
                  Nixpacks finally detected Python correctly!

   ROOT CAUSE: Belmo's Nixpacks ignores the Root Directory setting
   when detecting application type. It always scans the repo root.
   The Procfile tells Nixpacks the start command. The root
   requirements.txt tells Nixpacks it's a Python project.

 ISSUE 2: Empty start command
   Error: "/bin/bash: -c: option requires an argument"
   Cause: Nixpacks detected Python but had NO start command configured
          (the "start" phase was empty in the Nixpacks plan)
   Fix: Created Procfile at repo root with:
        web: cd backend && uvicorn app.main:app --host 0.0.0.0 --port $PORT
   Status: WORKING - app now starts successfully

 ISSUE 3: CORS_ORIGINS validation error
   Error: "pydantic_core._pydantic_core.ValidationError: CORS_ORIGINS
           Value error, Expecting value: line 1 column 2"
   Cause: User pasted placeholder text with comments as CORS_ORIGINS value:
          ["https://your-app.vercel.app"] (update after Vercel deploy)
          The parentheses and comments broke JSON parsing.
   Fix: Change CORS_ORIGINS to a valid value like:
        http://localhost:3000
        OR delete the CORS_ORIGINS variable entirely (has default)
   Status: NOT YET FIXED - need to fix in Belmo Environment tab
