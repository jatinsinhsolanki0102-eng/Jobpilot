 1. PLATFORM DECISION
 -----------------------------------------------------------------
 Render was chosen. It is NOT the ideal platform for a 24/7
 background agent (free tier sleeps after 15 min idle), so the
 backend MUST run on the paid "Starter" plan (~$7/month) to keep
 the APScheduler + Telegram bot alive around the clock.

   - Backend  : Starter (always-on)  -> required for the agent
   - Frontend : Free tier            -> fine, serves UI on demand
   - Database : Render Postgres (free / starter) -> see notes below

 2. WHAT IS ALREADY PREPARED IN THIS REPO (committed)
 -----------------------------------------------------------------
   - render.yaml          : Render Blueprint - one-click deploy of
                            Postgres + backend + frontend with all
                            cross-service env vars wired up.
   - backend/Dockerfile   : Python 3.12 + Playwright Chromium
                            (--with-deps), TZ=Asia/Kolkata, runs
                            app.seed (idempotent) before uvicorn,
                            listens on $PORT.
   - frontend/Dockerfile  : Node 22 + Next.js build, listens on $PORT.
   - backend/.dockerignore: keeps .env, .venv, logs, db out of image.
   - frontend/.dockerignore: keeps node_modules/.next out of image.
   - backend/app/config.py: CORS_ORIGINS accepts BOTH a JSON array
                            (local) and a plain URL / comma list
                            (Render injects the frontend URL via
                            fromService).
   - scheduler timezone   : Asia/Kolkata (daily summary 20:00 = 8 PM IST).
   - requirements.txt     : tzdata included so zoneinfo works.

 3. DEPLOY VIA BLUEPRINT (recommended, no CLI needed)
 -----------------------------------------------------------------
   1. Push repo to GitHub (already: github.com/jatinsinhsolanki0102-eng/Jobpilot).
   2. Render dashboard -> New -> Blueprint -> select the Jobpilot repo.
      Render reads render.yaml and proposes the 3 resources:
      - jobpilot-db       (Postgres)
      - jobpilot-backend  (web service, Starter)
      - jobpilot-frontend (web service, Free)
   3. Click Apply. Render prompts for the placeholder secrets:
      - GROQ_API_KEY        = <from backend/.env>  (optional, heuristic fallback if empty)
      - TELEGRAM_BOT_TOKEN  = <from backend/.env>  (optional, bot reports "not configured" if empty)
      Everything else (DATABASE_URL, SECRET_KEY, CORS_ORIGINS,
      NEXT_PUBLIC_API_URL, SCHEDULER_ENABLED) is wired automatically.
   4. Wait for both services to reach "Live" (first backend deploy
      takes a few minutes - Chromium install).
   5. Check backend logs for "Database ready", "Background scheduler
      started" and "Telegram bot polling started". Open the backend
      URL -> /health should return {"status":"ok",...}.
   6. Open the frontend URL in a browser. Register, upload resume,
      set preferences, browse ranked jobs, connect Telegram.

 4. DATABASE NOTES (IMPORTANT)
 -----------------------------------------------------------------
   - Render FREE Postgres expires 30 days after creation and is
     deleted. For a real deployment use the paid plan (Starter
     Postgres ~$7/month) or export/restore before the deadline.
   - To change the DB plan: Render dashboard -> your Postgres ->
     Settings -> Plan. (Blueprint may pin "free"; adjust manually.)
   - The backend creates tables automatically on first start via
     app.seed (create_all + 15 sample jobs) - no manual migration.

 5. TELEGRAM + SCHEDULER REQUIREMENT (IMPORTANT)
 -----------------------------------------------------------------
   - The Telegram agent + APScheduler live INSIDE the backend
     process (in-memory). If the backend sleeps (free tier) the
     hourly scans, daily summaries, weekly reports and alerts stop.
   - Backend MUST stay on Starter (or higher) plan. Verify after
     deploy that the service shows "Always On" under Instances.
   - After first deploy, restart the backend once from the Render
     dashboard if the bot did not start polling (token pickup).

 6. ENVIRONMENT VARIABLES SUMMARY (never commit secrets)
 -----------------------------------------------------------------
   Backend:  DATABASE_URL (auto), GROQ_API_KEY, TELEGRAM_BOT_TOKEN,
             TELEGRAM_BOT_USERNAME, SECRET_KEY (auto-generated),
             SCHEDULER_ENABLED=true, CORS_ORIGINS (auto)
   Frontend: NEXT_PUBLIC_API_URL (auto)
   Auto = wired by render.yaml via fromDatabase / fromService /
           generateValue. Do NOT paste backend/.env on the platform.

 7. CHANGING REGION / CUSTOM DOMAIN
 -----------------------------------------------------------------
   - Region is set to singapore (nearest to India) in render.yaml.
   - Optional: add a custom domain per service (Dashboard ->
     service -> Settings -> Custom Domain). If you change the
     frontend URL, CORS_ORIGINS and NEXT_PUBLIC_API_URL follow
     automatically on redeploy (they reference RENDER_EXTERNAL_URL).

 8. COST EXPECTATIONS
 -----------------------------------------------------------------
   - Backend Starter web service : ~$7/month
   - Render Postgres Starter     : ~$7/month (free tier deletes after 30 days)
   - Frontend Free               : $0
   - Total approx $14/month for a stable 24/7 agent with persistent DB.
     Delete the project in the dashboard to stop all costs.
